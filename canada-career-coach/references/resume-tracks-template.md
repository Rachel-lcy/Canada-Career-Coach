# Resume Tracks Template

A **track** is a resume version aimed at one role family. Applying with a single resume to every role usually dilutes the evidence; two to four tracks is a workable range. The coach recommends a track per posting, so each needs a clear definition.

## How to define a track

| Field         | What to write                                                                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Name          | A neutral label, such as "Web Developer", "IT Support / Help Desk", "Business / Data Analysis"                                                               |
| File          | Filename of the resume version                                                                                                                               |
| Target roles  | Job titles it is meant for                                                                                                                                   |
| Framing       | What the first third of the page emphasizes (shipped projects and front-end skills, troubleshooting and customer service, analysis and reporting, and so on) |
| Lead evidence | The 3–4 achievements that come first                                                                                                                         |
| Vocabulary    | Terms this track uses on purpose                                                                                                                             |
| Not claimed   | Things this track deliberately does not claim, even if the posting asks                                                                                      |

## Example (fictional person)

Alex is a fictional recent web development diploma graduate in Calgary with a part-time retail job and some volunteer tech support. Alex keeps two tracks. Every organization and project below is invented.

**Track 1: Web Developer (main track)**

| Field         | Example                                                                                                                                                                                       |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Name          | Web Developer                                                                                                                                                                                 |
| File          | `resume-web-developer.pdf`                                                                                                                                                                    |
| Target roles  | Junior Web Developer, Front-End Developer, WordPress Developer, Web Content Developer                                                                                                         |
| Framing       | Shipped projects, front-end skills, responsive and accessible design                                                                                                                          |
| Lead evidence | Capstone: booking website for a fictional community dance studio, built with React and deployed with a live link; personal portfolio site with four projects; front-end developer certificate |
| Vocabulary    | HTML, CSS, JavaScript, React, responsive design, accessibility (WCAG), Git and GitHub, REST API, Figma                                                                                        |
| Not claimed   | Professional paid development experience; back-end systems in production; senior architecture decisions                                                                                       |

**Track 2: IT Support (backup track)**

| Field         | Example                                                                                                   |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| Name          | IT Support / Help Desk                                                                                    |
| File          | `resume-it-support.pdf`                                                                                   |
| Target roles  | IT Support Specialist, Service Desk Analyst                                                               |
| Framing       | Troubleshooting, user communication, documentation                                                        |
| Lead evidence | Volunteer tech support at a community centre; home-lab Active Directory setup; customer service in retail |
| Vocabulary    | ticketing, troubleshooting, Microsoft 365, Active Directory, knowledge base                               |
| Not claimed   | Production network administration                                                                         |

**How the coach would use them:** for a "Junior Front-End Developer" posting it recommends Track 1. If the posting also mentions "supporting internal users" or "troubleshooting website issues", it may suggest borrowing the volunteer tech-support bullet from Track 2, because it is true and relevant. If the posting asks for "2+ years of professional React experience", it reports that as a gap; the capstone and portfolio are project experience, not paid experience.

## How the coach uses tracks

1. Extract the posting's keywords and seniority signals.
2. Score each track by overlap and by whether the lead evidence matches what the posting values most.
3. Recommend one base track. Suggest borrowing a bullet from another track only when it is true and relevant.
4. Report which posting requirements no track can support. These are gaps, not instructions to add claims.

## Consistency checks across tracks

- Same dates, titles, employers and metrics everywhere.
- Same headline numbers (budget, team size, project count) in every version.
- Differences should be in emphasis and order, not in facts.

## Tip: showing your tracks publicly

If you publish an example, use a fictional person and fictional organizations. Real file names or employer-specific versions reveal where you applied.
